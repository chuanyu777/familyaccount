## 阻断结果

真实 DeepSeek `/models` 返回的模型只有：

- `deepseek-flash`
- `deepseek-v4-pro`

使用指定的 `deepseek-v4.1-flash` 发起真实助手请求时，DeepSeek API 返回 HTTP 400：该模型名不在当前 API 支持列表中。后端因此向客户端返回 `INTERNAL_ERROR`，没有产生助手回答，也没有执行任何记账写入。

这说明当前版本已完成真实 Docker、真实后端、真实 Agent、真实 DeepSeek API 的联通，但无法在指定模型名被 API 拒绝的前提下继续进行模型能力评估。测试没有改用其他模型，也没有用 Mock 结果替代。

## 结论

当前阻断项是模型名称/API 可用性不匹配，不是旧 Docker 代码或本地测试环境导致。要继续完成查询、记账草稿、确认写入、边界拒答等真实模型测试，需要先确认 DeepSeek 侧提供可调用的准确模型 ID；在此之前，任何声称“已完成 `deepseek-v4.1-flash` 真实模型评估”的结果都不成立。

## 第二轮：`deepseek-flash` 真实模型测试

用户确认改用 DeepSeek API 支持的 `deepseek-flash` 后，使用当前分支源码重新构建并启动同样的独立 Docker 栈，重新完成了真实 API 测试。

### 通过场景

- 查询本月收入、支出、结余：金额与后端账目一致。
- 支出分类、账户余额、年度收支、资产负债净值查询：均能调用后端工具并返回正确结果。
- 投资建议边界：拒绝推荐股票，并将话题引回记账/查账。
- 自然语言记账：生成 45 元买菜支出草稿，确认前未写入。
- 多轮确认：确认后真实写入交易；重复确认不重复写入。
- 创建账户：生成账户草稿，确认后真实创建账户并写入初始余额。
- 投资买入：显式指定账户 ID 后正确生成组合草稿；确认后创建资产并扣减账户，收支统计不变。
- 信息不完整：缺少金额、分类等关键字段时先澄清，没有猜测写入。
- 消息持久化：用户消息、模型回答和草稿卡片均写入助手会话。
- 未登录访问助手接口：返回 HTTP 401。

### 发现的问题

1. 转账场景失败：用户说“从默认账户转到银行卡”时，Agent 没有把转入账户传给 `propose_create_transaction`；后端工具调用返回 502，前端看到 `INTERNAL_ERROR`。当前 Python 工具签名没有 `to_account_id` 参数，转账无法完成。
2. 取消语义不完整：用户说“取消这笔草稿”后，模型回答不执行，但草稿仍是 `PROPOSED` 待确认状态；当前 Agent 没有取消待确认草稿的工具。测试随后通过真实后端取消接口清理该草稿。
3. 投资买入依赖账户 ID：用户只说“使用默认账户”时，模型未稳定补齐 `accountId`，导致工具调用失败；明确说“账户 ID 1”后完整通过。工具层可考虑支持默认账户或强制先调用 `list_accounts`。
4. 内部工具错误 Token 会被包装成 HTTP 500，而不是 401；鉴权实际拒绝，但错误码不够准确。

第二轮结论：`deepseek-flash` 的真实 Docker 联调已可运行，核心查询和确认写入链路通过；转账、取消草稿和部分默认账户推断仍需修复后才能通过完整验收。

## 第三轮：缺陷修复与真实回归

已完成以下修复：

- Agent 转账工具增加 `to_account_id`，并向后端传递 `toAccountId`。
- 新增 `cancel_pending_action`，支持在对话中取消最近一张待确认草稿。
- 投资买入未提供 `accountId` 时，由后端确定性选择账本默认账户。
- 内部工具错误 Token 改为统一 `ApiException`，返回 HTTP 401；未知工具返回 404。
- 修复待确认草稿摘要中的转义错误，模型现在能看到真实 action id、类型与字段值。

自动化回归结果：

- Agent Python：23 项全部通过。
- 后端助手定向测试：全部通过。
- 后端全量测试：全部通过。
- Web 助手面板：6 项全部通过。

真实 Docker + `deepseek-flash` 回归结果：

5. Agent 与后端日志未出现未处理异常或 5xx。

第三轮结论：第二轮发现的四项问题均已修复并通过自动化与真实模型回归。
