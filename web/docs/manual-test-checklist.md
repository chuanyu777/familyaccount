# Web 手工验收清单

环境：`https://<域名>`；测试日期/版本：________；执行人：________。准备预置平台管理员、特殊账本 owner/member、另一账本及可回滚的测试数据，并在浏览器开发者工具中查看 Network、Cookies 和 Console。每项记录 `通过/失败/阻塞`、实际响应码和证据链接；写入操作仅对测试数据执行。生产边界见 [部署说明](../../deploy/README.md)。

| 结果 | 场景与操作 | 可观察的通过条件 |
| --- | --- | --- |
| [ ] | 桌面和手机视口分别直接打开并刷新 `/platform`、`/platform/ledgers`、`/platform/ledgers/<有效ID>`、`/ledger`、`/ledger/`。 | 每个 URL 返回 SPA 文档和资源；平台路径显示平台登录或只读视图，账本路径显示账本登录或特殊账本；刷新后不跳到另一入口，页面无布局遮挡和控制台错误。 |
| [ ] | 未登录打开 `/platform`，用预置平台管理员登录；搜索账本名称及 ID，分别打开现存账本和不存在的 ID，再返回。 | 登录接口为 `POST /api/auth/platform/login`；列表和详情由 `/api/platform/ledgers` 提供。平台管理员可检查任一现存账本的详情；不存在的账本 ID 返回 404。详情可查看成员、账户、分类、交易、资产、负债及还款等已批准只读区块；没有创建、编辑、删除、归档、邀请或绑定码控件。尝试平台写接口被服务端拒绝。 |
| [ ] | 未登录打开 `/ledger`；在**未绑定小程序**前分别用预置 owner 和 member Web 账号登录。 | `POST /api/auth/web/login` 可独立成功；只呈现配置的特殊账本及当前角色，没有账本切换器；普通用户账号不能通过这两个 Web 登录入口进入。 |
| [ ] | 仅保留 `platform_session` 请求账本 API；仅保留 `ledger_session` 请求平台 API；两个 cookie 同时存在时分别操作。 | 交叉调用由服务端拒绝（401/403），无另一账本数据；两个入口各使用自己的会话。活动入口收到 401 后仅回到自己的登录页，不显示旧数据；平台详情收到 403 时保留平台会话并显示权限错误。 |
| [ ] | member 创建/编辑/删除自己的交易及还款，再尝试改动另一成员的记录；owner 重复跨成员操作。 | member 自己的写入成功、他人的写入被服务端拒绝；owner 可按角色规则管理两人的记录。表单不提供成员归属选择器，提交的归属由服务端确定。 |
| [ ] | 分别以 owner 和 member 会话创建/编辑共享资源：账户名称、资产名称/类型/当前估值、负债名称/本金/月供/还款日、分类名称；对资产快照创建或更新月份估值和备注。随后 member 尝试归档/恢复资源，owner 对适用资源执行归档/恢复。 | member 和 owner 均可创建/编辑账户、资产、负债和分类；两种角色均可创建/更新资产快照。账户、资产、负债、分类的归档及恢复仅 owner 可执行；member 的控件不可见且直接请求被服务端拒绝。快照属于资产记录，不提供独立归档/恢复。owner 操作成功，重新加载后状态一致。 |
| [ ] | 登录账本后在设置页生成绑定码、复制、检查到期时间并重新生成；在小程序用新码绑定。 | 仅已认证的账本用户可 `POST /api/auth/binding-code`；显示十分钟有效期，复制内容与码一致，新码可在小程序绑定，已使用或过期的码被拒绝。重新生成不会自动撤销先前未使用的码。平台与两个登录页均无绑定码。 |
| [ ] | 同一浏览器同时登录两个入口，分别退出平台和账本；HTTPS 下重复并检查 Cookies。 | `POST /api/auth/logout?kind=platform` 仅清 `platform_session`；`kind=ledger` 仅清 `ledger_session`；另一个入口仍可用。重新加载已退出入口显示自身登录页。登录 cookie 为 `HttpOnly; SameSite=Strict; Path=/; Secure`；退出后对应 cookie 不再发送。 |
| [ ] | 让两个会话分别过期或替换为无效值，再刷新并请求数据。 | `GET /api/auth/session?kind=platform|ledger` 分别拒绝无效会话；各入口回自己的登录页，不再显示上次的受保护数据或写入控件。 |
| [ ] | owner 分别归档共享账户、资产、负债和分类；member 打开相关新建/编辑选择器；owner 恢复后再检查。 | 已归档账户、资产、负债和分类不出现在相应可用选择器中；member 不能归档或恢复；owner 可恢复，恢复后可再次选用。资产快照随所属资产查看，不独立归档/恢复。 |
| [ ] | 以已登录特殊账本用户身份，向账本 API 提交另一账本的 `X-Ledger-Id` 或资源 ID，并尝试读取和写入；另以平台管理员打开任一现存账本详情及一个不存在的账本 ID。 | 账本用户的伪造账本/资源 ID 请求被服务端拒绝且不返回外部账本数据；平台管理员可读取任一现存账本详情，不存在的账本 ID 返回 404。该 404 是资源不存在，不是跨账本权限拒绝。 |
| [ ] | 在生产样式部署中访问公网 `http://<域名>/platform` 和 `/ledger`，再访问 HTTPS 两入口、深层路径及 `/healthz`。 | 公网 HTTP 由外部网关重定向到 HTTPS；HTTPS 页面、资源和刷新正常；`GET /healthz` 到后端；`/api` 与页面同源，登录响应的 `Set-Cookie` 未被代理改写且 Secure cookie 被浏览器保存/发送。容器 Nginx 本身只监听 HTTP。 |
